# 智能电表负荷分析平台

面向供电所稽查场景的**纯本地**浏览器分析工具：15 分钟级智能电表负荷数据的导入、清洗、负荷聚类、
窃电嫌疑排查与稽查反馈闭环。全部计算在浏览器 Web Worker 内完成，曲线数据存于 OPFS 本地磁盘，
**数据不出本机，无任何网络上报**。

## 快速开始

```bash
npm install
npm run dev        # 打开 http://localhost:5173
```

构建与本地预览：

```bash
npm run build      # 类型检查 + 生产构建（输出 dist/）
npm run preview
```

首次使用在「数据导入」页点击 **生成并跑通全流程**，内置生成器会构造可复现的测试数据集
（默认 5 万户 × 365 天 × 96 点/天），自动跑完清洗、聚类、线损、打分全流程。

## 五大功能页

| 页面 | 能力 |
| --- | --- |
| 数据导入 | 内置测试数据生成（5 种窃电模式 + 质量问题 + 换表/倍率事件）；外部档案/事件/供电量 CSV 导入；本地存储占用与全流程耗时 |
| 数据清洗 | 倍率校正、缺测补齐、冻结值/跳变值识别；问题总览、问题户清单、单户清洗前后逐日曲线对照 |
| 负荷聚类 | 日负荷曲线 L1 归一化后 k-means（轮廓系数选 k，抽样拟合+全量分配）；各簇典型曲线、户数、类型构成、成员名册 |
| 嫌疑排查 | 四维嫌疑打分与证据拆解；按台区/类型/簇/分数/稽查状态筛选排序；权重调参实时重算；名单导出；点户查看历史曲线 |
| 稽查反馈 | 稽查结果回填（确认/排除/待处理 + 手法 + 备注）；Top-N 命中率、分桶精确率、分模式召回随反馈重算；报告导出 |

## 窃电检测模型

四个子分均为该特征在全体用户中的**百分位位次（0~100）**，加权合成总分，默认权重 40/28/22/10：

1. **负荷突降（40%）**：相对同簇 peers 的电量走低、下行突变强度（MAD 稳健归一）、
   低尾天数占比、持续偏低占比，叠加绝对突降/突变信号；
2. **同类用户偏离（28%）**：归一化曲线与所属簇中心的 L1 距离 + 后期/前期相对波动比；
3. **台区线损关联（22%）**：用户月度电量与台区线损率的负相关强度 + 台区线损绝对水平；
4. **数据质量（10%）**：缺测/冻结/跳变异常点占比。

每个分数在用户详情中都可下钻到**具体贡献特征与原始数值**。

### 测试数据埋入的 5 种已知窃电模式

恒定分流、夜间旁路（20:00–07:00）、间歇性窃电（随机日少计）、缺相运行（周期性整段低计）、
渐进式改表（少计比例随时间增大）。另注入缺测、整天冻结、尖峰/突降跳变三类数据质量问题，
并为约 12% 用户生成换表/倍率变化事件。

## 本地数据架构（面向 5 万户 × 35040 点 ≈ 17.5 亿数据点）

- **OPFS 分块二进制**：每 1000 户一个块，`reported/truth` 两条 Float32 曲线 + 按天倍率轨迹，
  Worker 内用 `createSyncAccessHandle` 同步句柄高吞吐读写；
- **常驻内存仅放分析结果**：每户 96 点典型曲线、日电量与紧凑特征（约百 MB 级），
  单户历史曲线按块从磁盘按需读取并缓存；
- **14 个 Web Worker 并行**：生成、清洗、特征、台区线损按块并行，聚类抽样在主线程执行；
- 算法模块（`src/lib/*`）与 DOM 完全解耦，可在 Node 直接跑基准。

## 性能与模型实测

| 规模 | 环境 | 端到端耗时 |
| --- | --- | --- |
| 5 万户 × 365 天 | 浏览器 14 Worker（16 核/32GB 实测） | **6.47 分钟（目标 10 分钟）** |
| 1 万户 × 365 天 | 同上 | 83 秒 |
| 5 万户 × 365 天 | Node 单线程基准（`npm run bench`） | 约 5.3 分钟（仅算法，不含 UI） |

模型命中率（5 万户测试集，2000 个埋入窃电户）：Top100 精确率 94%、Top500 精确率 81%。

## 测试脚本（零依赖，驱动本机无头 Chrome 的 CDP）

```bash
npm run bench       # Node 单线程算法基准 + 模型命中率（可传参：node scripts/bench.ts 2000 365）
npm run e2e         # 浏览器端到端：20 项功能检查（生成→清洗→聚类→嫌疑→稽查→导出→刷新持久化）
npm run scale       # 浏览器 1 万户规模计时
npm run scale:50k   # 浏览器 5 万户规模验收
```

E2E/规模脚本需要先 `npm run dev`，并以远程调试端口启动 Chrome：

```bash
chrome --headless=new --remote-debugging-port=9222 --user-data-dir=<临时目录> http://localhost:5173/
```
